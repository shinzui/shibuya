# Agent Instructions

## Benchmarking Scope

- Treat the user's requested benchmark scope as fixed. Use the existing benchmark workflow and runbook as-is.
- If benchmarking requires changes to tooling, new profiles or variants, additional measurement or calibration, or substantial setup, report the limitation and ask for permission **before** doing that work.
- Requests to work autonomously or unblock yourself authorize work within the agreed scope. They do not authorize expanding it.
- Do not introduce additional acceptance or completion requirements. Do not call the original task incomplete because of requirements you added.
- Finish the requested implementation using the evidence already available. Record the observed results and their limits accurately; do not claim validation that was not performed.
- Any expansion of the benchmark scope requires an explicit user request or prior permission.
